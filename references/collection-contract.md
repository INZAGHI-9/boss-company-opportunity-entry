# Boss 岗位采集合同

本合同让不同 Agent、不同浏览器和不同操作系统产出同一份分析输入。采集方法可以不同，输入质量要求相同。

## 允许的方式

使用当前技能目录中的 `scripts/collector/boss-company-scout.mjs` 及其专用 Chrome 会话。不得调用、安装或依赖其他 Boss 采集技能、工作区临时脚本或其他浏览器档案。

不得复制 Cookie、读取账号密码或验证码、伪造设备信息、轮换代理，或绕过 Boss 的安全验证。页面出现“访问受限”“账户存在异常行为”“限制访问”、验证或登录失效时，首次出现即暂停，保留触发问题的页面与断点，等待用户手动恢复；不得自动重试、刷新或继续等待。若采集进程仍在运行但 30 秒内断点数量或更新时间没有变化，必须主动检查专用 Chrome 页面并按同一规则暂停。

## 采集顺序

1. 检查已登录状态；未登录时引导用户在专用浏览器会话中登录。
2. 用 `--company "目标公司"` 搜索候选主体，保存候选名称、Boss `brandId` 和公司主页链接。名称相似时，按公司名匹配度、公开岗位卡数量和稳定排序自动选择，不向用户请求选择；将全部候选、选择依据和置信度写入快照。低置信度仍继续采集，但必须在报告数据校准处提示。
3. 从确认主体的公司招聘页先读取当前显示的职位类型标签。排除“全部”标签后，逐类读取列表及完整 JD；标签名称、数量和链接必须以当前页面为准，不能写死。每次新运行都必须重新读取各类列表的全部分页，不能复用上一轮的页码-岗位缓存；仅可复用已完成 JD。每类先读取真实末页或接口分页结束信号；仅在该信号可用时使用固定 3 个可复用工作页并行读取，不能用首页卡片数推测页数。每个剩余分页任务在导航前随机等待 0-2 秒，以降低集中跳页的请求峰值；这不改变受限后的立即暂停规则。各类岗位按岗位 ID 合并；即使当前平台标签看似互斥，仍保留去重和交集记录作为安全兜底。
4. 同一专用 Chrome 同时只能运行一个采集命令。岗位详情的唯一主来源是点击岗位卡片后右侧已渲染的 JD，不能因详情接口未返回而判为缺失或等待接口超时。页面渲染错误仅在原工作页重试一次，之后按单页续采；单个岗位卡片已不可见时必须继续读取该页其余岗位。所有单页续采结束后，允许刷新岗位列表一次以核实动态下架；之后不循环刷新页面。

## 完整性

能确认公司页公布岗位总数时，只有以下条件同时成立才可标为完整快照：

- 每个可见职位类型均已遍历至其真实末页；
- 按岗位唯一标识合并后的数量等于公司页公布总数；
- 每个纳入岗位都有岗位链接和非空 JD。

若全部职位类型均已遍历、每个纳入岗位都有岗位链接和非空 JD，且公司页总岗位数与合并结果的缺口不超过 10%，可标为 `tolerated_gap`。若个别列表内岗位在读取 JD 时消失，须先完成一次列表刷新；刷新后仍不可读的岗位只可在上述 10% 总缺口内从本次快照剔除。必须记录总数、实际数、缺口数、缺口比例、每个标签的标注数/实际数和标签交集，不得写成逐岗零缺失或全国全部岗位。

缺口超过 10%、任一标签未遍历到末页、岗位详情未读全、页数上限触发或列表故障时，标为 `partial`。不得因“全部”标签最多显示 200 条而把该标签当作列表终点或完整性依据。

平台没有提供岗位总数时，记录实际分页结束依据并标为“可见岗位快照”，不要声称全国全部岗位。

## 标准分析输入

分析开始前生成 `analysis-input.json`。字段名可按当前 Agent 的实现调整，但必须包含以下信息：

```json
{
  "company": {
    "name": "目标公司名称",
    "brandId": "平台主体标识或 null",
    "companyUrl": "公司主页链接或 null"
  },
  "snapshot": {
    "collectedAt": "ISO 时间",
    "status": "complete | tolerated_gap | partial | visible_snapshot",
    "publishedJobCount": 0,
    "deduplicatedJobCount": 0,
    "limitation": "采集限制，包括允许的动态缺口（如有）"
  },
  "jobs": [
    {
      "jobId": "岗位唯一标识",
      "title": "岗位名称",
      "url": "岗位详情链接",
      "location": "城市或地区",
      "salary": "薪资原文或 null",
      "employmentMode": "用工方式或 null",
      "description": "完整 JD 原文"
    }
  ]
}
```

原始岗位内容必须保留在当前 Agent 的授权工作区，不得作为无关样本、日志或公开材料传播。保存分析输入与报告时，按 [交付位置预设](delivery-policy.md) 选择目录。
