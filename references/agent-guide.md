# 执行指引

## 工作顺序

1. 按 [采集合同](collection-contract.md) 确认目标公司主体，取得 `analysis-input.json`；`tolerated_gap` 仍可用于判断，但必须把岗位覆盖缺口保留在报告边界中。
2. 从全量 JD 与允许的目标公司官方资料提取产品/服务、客户、交易或交付动作、职责链和成功指标，并保留原文锚点。
3. 先建立仅供内部使用的客户事实、已观察的增长工作流、关键未知和产品匹配判断，再读取我方上下文选择销售入口；不得用产品倒推客户事实。关键未知只记录目标资料没有覆盖、且会影响本轮入口判断的事实。
4. 将判断整理为 `reportBlocks`：结论、入口总览、已观察事实、首轮验证、入口行动和资料边界。每条解释性事实、未知或行动只能分配给一个块；链接可在事实首次出现处引用。
5. 按“结论 → 总览 → 已观察事实 → 首轮验证 → 进入行动 → 资料边界”生成同一份报告；不需要用户额外确认。
6. 按 [交付合同](delivery-contract.md) 落盘并校验。

## 证据边界

- 客户业务事实只能使用目标公司证据；我方产品、通行做法或行业印象不能补全未知字段。
- 产品入口只能使用客户业务事实和 `our_company_context` 中已有的产品、客群、工作流与能力；“我方能解决”不是匹配依据。
- 工具提及、岗位职责或业务动作仅是相关性线索；只有明确问题、目标或流程信息才是需求证据。
- 目标岗位不是采购决策人，只能写建议优先接触的职能或岗位类型。
- 招聘需求不等于预算、项目立项、采购意向、客户关系或成交概率。
- “未观察到”只表示本次允许资料未覆盖该事实；必须说明它限制了哪一个入口判断，不能写成客户存在流程问题、工具缺口或采购意向。
- 首轮必须围绕推荐入口确认具体工作量、协作方式、决策目标、现有工具或决策链中仍未知的部分；不使用跨公司的固定问题清单。
- 结论只给约谈判断与采购边界；总览只给产品、建议接触职能、业务开场和首场目标；已观察事实不推荐产品；首轮验证不提供解决方案；进入行动不复述岗位事实或未知；资料边界只保留快照和全局证据限制。

## 自动止步条件

若产品/服务、目标客户、交易或交付方式、可见业务动作中没有任何可追溯的基础事实，在同一份报告中写明“本轮不推产品”并止步于产品讨论之前。若我方上下文为 `null`，或无产品能通过三项入口门槛，`reportBlocks.entries` 与 `reportBlocks.entryActions` 为空，`reportBlocks.firstValidation` 的 `entryId` 为 `null`，并写明下一场应确认的事实。支持进入时，每个入口必须回链客户业务事实，并给出首场会目标、推进信号和止步信号。
