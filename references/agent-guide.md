# 执行指引

## 工作顺序

1. 按 [采集合同](collection-contract.md) 确认目标公司主体，取得 `analysis-input.json`。
2. 从全量 JD 与允许的目标公司官方资料提取产品/服务、客户、交易或交付动作、职责链和成功指标，并保留原文锚点。
3. 先在报告的客户业务底稿章节完成客户事实，再读取我方上下文生成我方业务匹配诊断；不得倒置顺序。
4. 在同一份报告中写商机切入或止步判断；不需要用户额外确认。
5. 按 [交付合同](delivery-contract.md) 落盘并校验。

## 证据边界

- 客户业务底稿只能使用目标公司证据；我方产品、通行做法或行业印象不能补全未知字段。
- 我方业务匹配诊断只能使用客户业务底稿和 `our_company_context` 中已有的产品、客群、工作流与能力；“我方能解决”不是匹配依据。
- 工具提及、岗位职责或业务动作仅是相关性线索；只有明确问题、目标或流程信息才是需求证据。
- 目标岗位不是采购决策人，只能写建议优先接触的职能或岗位类型。
- 招聘需求不等于预算、项目立项、采购意向、客户关系或成交概率。

## 自动止步条件

若产品/服务、目标客户、交易或交付方式、可见业务动作中没有任何可追溯的基础事实，在同一份报告中写明底稿缺口并止步于产品或方案讨论之前。若我方上下文为 `null`，或匹配诊断结论为不匹配，也在同一份报告中写明诊断缺口和止步原因。支持进入时，每个进入话题必须回链到底稿和匹配诊断中的事实，并列出进入条件。
